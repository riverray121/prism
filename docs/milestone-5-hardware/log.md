## Notes

- Spec-time decisions: hubs own their light config (stock WLED, no custom firmware); hub identity is the MAC address; patch is per-song in the mapping doc; no schema version bumps — the schema changes in place while the app is pre-release; stopped playback means the strip is off, no fallback looks.
- The frame sampler runs in the webview render loop this milestone; moving it into the Rust shell (show shipped to Rust, transport mirrored) is milestone 6 (`rust-sampler` in `../index.md`). Lights stall if the window is minimized during playback until then.
- Bench rig this milestone builds against: `../hardware/rig.md` (ESP32 + WLED 16.0.1, WS2812B 300 px, DDP on port 4048).
- `setPatch` lives in `mapping.svelte.ts` (it edits the mapping doc; also keeps hardware→mapping imports one-directional for state init), not hardware state as implementation.md sketched.
- Rig light entries store `pixel_count` but not WLED's output `start` offset; a multi-output hub would need it for DDP buffer addressing. Single-strip milestone — deferred.
- Streaming runs only while the Hardware tab is visible (the rAF loop is hosted by HardwareView, which also owns evaluation refresh when Mapping is closed). The M6 Rust sampler lifts both limits.
- Discovery races the webview: mDNS resolves land within the first second of app startup, before the frontend's event listener attaches, and WLED re-announces on hour-scale TTLs. The shell keeps a found-hubs map and exposes `discovery_snapshot`; the frontend pulls it right after attaching. Verified on the bench log (`mdns found wled-bbc85c` at startup).
- Connect new has a manual Add-by-IP fallback (`probeAddress` in hardware state) for networks where multicast is blocked, with checking/failed feedback in the panel. Scanning is a 15 s UI window (`scan`/`startScan`): spinner (ProgressRing quarter-arc + `animate-spin`) while open, a Scan again button after — the shell's mDNS browse itself never stops; Scan again just re-pulls the snapshot.
- Patch renders as aligned full-width rows (`grid-cols-[1fr_3rem_1fr]`): linked program–light pairs sorted first and joined by an accent string across the gutter; unlinked programs/lights fill the remaining rows side by side.
- The state modules (`src/lib/state/`) must stay an acyclic import graph. M5 briefly cycled `mapping ↔ inspection` and `mapping ↔ hardware`; Vite HMR then resolved hot-updated modules to undefined (`module.default` TypeError bursts in app.log) and wedged the whole reactive graph — symptom: scrubbing and every store-driven update dead app-wide until relaunch. The cut: evaluation (outputs, matrices, `ensureEvaluationCurrent`) lives in `state/evaluation.svelte.ts`, downstream of mapping/inspection/hardware; it invalidates its own caches by song id + raw-profile identity instead of exposing reset hooks; `streamTick` takes outputs as an argument rather than importing the store.
- rAF loops hosted in `$effect` must schedule their first tick through `requestAnimationFrame`, never call it synchronously: a sync first call runs inside the effect's tracking scope, so every state read (`transport.currentTime` at 60 Hz) becomes a dependency and the effect tears down/restarts per frame. In HardwareView that meant a blackout + WLED power toggle per frame once playback started, flooding the shell's HTTP path until the UI (including transport-bar scrubbing) went dead.
- Light-delay calibration: the streamer samples `latency_ms` behind the playhead (rig field, default 60 ms, Sync row in the Devices panel with ±10 ms nudge, clamp 0–500). Absorbs the constant lights-lead-audio stack: centered smoothing (~40 ms), centered analysis frames (~10–25 ms), audio output latency (~10–25 ms built-in; 150 ms+ on Bluetooth — recalibrate per output device).
- Streaming and evaluation refresh are app-lifetime (`state/stream.svelte.ts`, an `$effect.root` hosted by the shell route): the strip keeps playing on any tab, and outputs stay current with no Mapping/Hardware view mounted. MappingView/HardwareView no longer host those effects. Remaining webview limit until the M6 Rust sampler: rAF throttling when the window is minimized.
- Scrubbing (and panel resize) run on MOUSE events, not pointer events. The app-wide dead-scrub outage: this WKWebView stopped delivering `pointerdown` to handlers entirely (`pointermove`, `mousedown`, `mouseup`, `click` all still dispatch — verified with document-capture probes and synthetic CGEvent clicks), and TimeAxis + ResizablePanel were the only pointer-event consumers, so every scrub surface died silently while click-driven UI kept working. M5 never touched the input path (`git diff` clean over graphs/transport/shell against the last working commit); the trigger was environmental. The interaction layer must not depend on pointer events; drags track on window listeners in place of pointer capture.
- Vite full-reloads the page for any changed project file outside the module graph (its fallback for unimported files) — docs edits, sidecar .py edits, and library writes (mapping/rig/profile saves) were all restarting the app mid-use, and colliding reloads during HMR are what wedged the module graph. `server.watch.ignored` in vite.config.js now excludes `docs/`, `library/`, `sidecar/`, `tests/`, `*.test.ts`, and `src-tauri/`.
- `console.warn`/`console.error` mirror into app.log (health.svelte.ts): the app's guard rails (schema drops, failed track loads, muted bindings) report through the console, which a closed webview otherwise takes with it.
- The unclean-exit banner is release-only (`!cfg!(debug_assertions)` in lib.rs): dev-watcher rebuilds SIGKILL the app, stranding `session.lock`, which made every Rust edit masquerade as a crash. The stale-marker log line still records in both build types.
- `uvx ruff check sidecar/` reports 10 pre-existing errors (newer ruff rules, `datetime.UTC` etc.) untouched by this milestone; fold into the repo-wide `/clean`.
